## Socket ownership

The opened route preconnects only a running native terminal. Cached native metadata also triggers it. The view provides a fallback before xterm imports. The existing transport adopts the same socket with the same URL (including handoff identity and replay/ack parameters); open and message events drain in wire order after handlers are installed. No preconnect sends, grid claims, resizes, input, OSC replies or acknowledgements occur. Fit and layout settlement still own the first grid. Abandonment, a ten-second expiry, two pending sockets and a 24 MiB frame budget bound unconsumed resources. Close and overflow use the normal transport fallback.

Sidebar hover/focus retains existing metadata, module and screen warming. Full attach is deliberately excluded from intent: `completePendingAttach` can invoke `repaintReopenedNativeTerminal`, and attachment changes the server watcher/flow registry. It is not a side-effect-free hover primitive.

## Screen-first design deferred

The server screen path has serialized bytes and a sequence checkpoint, but the preview is not an independently live terminal. A screenshot/string of rows cannot preserve cursor, modes, alternate-buffer state and a partially received escape sequence. The current replay uses historical grid markers and swaps only after ordered parser completion.

A future server-only attach mode should obtain an atomic complete snapshot plus checkpoint S from the screen worker, register live buffering before taking that checkpoint, restore it in a separate foreground xterm, then deliver only chunks at or after S. If the checkpoint cuts a chunk or parser sequence, preserve the pending bytes and exact offset or fall back to full replay. The existing auth and device ownership path remains authoritative.

Older history must replay in a separate background terminal/archive. Xterm's public write API appends to the active buffer; it cannot insert old output above a live viewport. Replacing private buffer internals risks cursor/mode corruption and marker invalidation. A separate history viewer or a fully synchronized buffer swap is needed, with explicit handling of resize, alternate-screen transitions, wrapping, selection, search, scroll anchors, truncation and history/live overlap. Sequence and grid compatibility need tests before exposing input during restoration. No protocol or daemon change is introduced here.

## Measurement handoff

Run `node scripts/p38-terminal-timing.mjs webkit SEEDED_THREAD_URL output.json` and repeat with `chromium` for both baseline and candidate dist. The script only navigates, waits, evaluates and observes WebSocket frames. It never clicks, types, presses or injects input. It stores frame metadata, resource timings, grids, replay checkpoint endpoints and acknowledgements without retained terminal text or handoff tokens. Use three independent script invocations per build for three cold-context runs and interleave baseline/candidate. Warm runs reuse the context cache but use a fresh page. Baseline parsing uses the final output acknowledgement when the explicit candidate parser mark is unavailable.
