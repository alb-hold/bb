# Shared frontend runtime

Frontend builds replace the specifiers in `src/runtime-shims.mjs` with the existing host runtime slots. Radix checkbox, slot and compose-refs load together through an awaited lazy runtime group before plugin evaluation. Their namespace objects are assembled in a separate chunk using the host's installed modules. No SDK surface is added.

For these three specifiers, an import with no resolvable plugin copy uses the host runtime slot, preserving scaffold builds before dependencies are installed. When the plugin copy resolves, the builder reads its installed version and shares only when the host has the same major and an equal or newer stable version. Prereleases require an exact match. An unreadable version, newer plugin version or incompatible major keeps the resolved plugin copy bundled and emits a build warning. The generated export manifest records the host's actual installed versions.

The complete Radix package namespace is shared, including Checkbox Root and Indicator, to preserve context identity. Existing plugin artifacts keep their bundled dependencies until rebuilt. Rebuilt artifacts declare the new slots in `app.meta.json`; the loader awaits them before evaluation. If loaded by an older host without a required slot, the shim throws a specific `Cannot load "<specifier>"` error and the loader contains the failure to that plugin. New artifacts require the updated host.

Zod admission is all-or-nothing for a plugin's transitive frontend source graph. Before any app bundle exists, generation walks the host boot entry's static source imports and collects directly used Zod export names. Nested namespace members are excluded because exposing their complete container would retain additional code. The generated facade uses only those names, excluding strictObject, NEVER, ZodError, never, email and intersection. It loads through the same awaited runtime groups. App builds need one pass; the boot budget remains the backstop against source graph over-inclusion.

A plugin shares Zod only when every use imports supported names statically or accesses those names statically on a namespace or z binding. Computed access, namespace escape or spread, re-exports, dynamic imports, unsupported subpaths and unsupported names keep all its Zod imports bundled, with a migration warning. The same resolved-version contract as Radix applies. An unresolved Zod import remains a preflight build error; it does not opt into host sharing. The admission preflight is reused for plugins that keep their copy; admitted plugins are rebuilt with the existing runtime shims. Older plugin artifacts retain their bundled copy.

Shared schemas and thrown errors have the host's constructor identity in both directions. Zod's error-map and locale configuration is global to its shared instance. Calls to config or setErrorMap are outside the admitted subset, so a plugin using them retains its own copy. First-party frontends currently have no such calls. Sharing does not add a public plugin API.

Zod remains a runtime dependency in scaffolds and migrations, rather than a shimmed type-only devDependency, because servers and frontend fallback builds still bundle it.
